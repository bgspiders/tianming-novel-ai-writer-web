## 三、关键技术决策

1. **Schema 驱动的前端**:把每个模块的字段、Tab、列表列、字段类型(text/textarea/select/number/switch/tags/date)声明在 `moduleSchemas.ts` 这一个 TS 数据文件中。`DesignView.vue` 用同一套表格 + 同一个 `DesignFormField` 组件渲染 11 个模块。新增模块通常只需:加 1 个 Schema + 1 个 API 模块 + 1 个 `apiMap` 入口,不动 UI 主体代码。
2. **CategoryService 用 ModuleType switch + 反射式 IQueryable 扩展**:`CountItemsByCategoryAsync` 用 `switch` 按 ModuleType 路由到对应 DbSet,共享 `GroupCountAsync<T>` 泛型方法。PromptTemplates 由于用字符串 Category(name)而非 CategoryId,单独实现 `CountPromptsByCategoryNameAsync` 按名匹配。
3. **删除分类的引用检查不按源书隔离**:`CountAllItemsAsync` 跨所有 SourceBook 统计 CategoryId == id 的实体,避免"按当前源书数为 0 通过删除,但其他源书还有引用"的逻辑漏洞(实际测试时发现的 bug,已修复)。
4. **InvalidOperationException → 400**:阶段 1.5+2 的中间件只把 `ArgumentException` 映射 400,本次新增的服务层用 `InvalidOperationException` 抛业务校验失败,扩展映射后才能正确返回 400 给前端,前端 axios 拦截器会把 `detail` 字段作为 `err.message` 弹出。
5. **`DesignBase` 接口让 TS 联合类型可统一**:11 个模块的 DTO 都实现 `DesignBase`(id/name/category/categoryId/isEnabled/sourceBookId/createdAt/updatedAt),前端 `DesignView.vue` 用 `Record<string, unknown>` 处理动态字段时只需把 list/get 返回值 `as unknown as Record<string,unknown>[]` 即可绕过 TS 严格类型。
6. **`/design` 重定向 + `/design/:module` 动态路由**:11 个模块共享一个 Vue 组件,通过路由参数切换。比拆成 11 个独立页面更适合 schema 驱动模式。
7. **生成规划层先并入设计工作台**:Outline / VolumeDesign / ChapterPlan / ChapterBlueprint 虽然语义上属于阶段 4 前置层,但数据结构与设计模块完全同构,因此先复用 `/design/:module` 的统一工作台与 CRUD 流程,降低交付成本。
8. **Picker 复用动态 schema**:不为每个字段单独写 UI,而是在 `FieldDef` 上新增 `pickerSource` / `pickerValue`。`DesignView.vue` 统一加载角色、势力、地点、分卷候选,`DesignFormField.vue` 只负责渲染 select/tags 的候选项。
9. **Project / Volume 先做全局上下文,暂不强制后端 scope**:当前设计表仍主要按 SourceBook 隔离;Project / Volume 先作为编辑工作台上下文与卷字段候选来源落地。后续进入章节生成与正文管理后,再把 ProjectId/VolumeId 贯穿到生成、校验、章节正文等运行态数据。
10. **Project 默认源书作为过渡 scope**:在不改 11 张设计/生成规划表结构的前提下,允许 Project 记录 `CurrentSourceBookId`,DesignView 切换项目后会自动带出默认源书,作为 Project scope 的轻量过渡方案。
