# 新手使用教程

这份教程面向第一次使用天命 Web 版的用户，目标是从零完成一次可落地的写作流程：登录、配置模型、开书、检查计划、自动生成章节、编辑和校验。

## 1. 启动并登录

### 本地开发

后端：

```bash
cd backend
dotnet restore
dotnet run --project src/TM.Web.Api
```

前端：

```bash
cd frontend
npm install
npm run dev
```

浏览器访问：

```text
http://localhost:38720
```

### Docker 部署

```bash
cd docker
docker compose up -d --build
```

浏览器访问：

```text
http://localhost:38721
```

### 第一次登录

首次打开系统时，需要先在前台设置管理员账号和密码。设置完成后，账号会保存到 SQLite，后续登录会使用长效 Cookie，默认有效期为 30 天。

如果页面提示 `no such table: app_users`，说明数据库结构还没有初始化或旧数据库缺少登录表。重启后端后再访问；如果仍然报错，请确认当前运行的是最新代码，并备份数据后重新初始化 SQLite 数据库。

## 2. 配置 AI 模型

进入：

```text
AI 模型
/settings/ai-models
```

按下面顺序操作：

1. 新增一个模型配置。
2. 填写 Endpoint、模型名和 API Key。
3. Endpoint 使用 OpenAI 兼容地址，例如 `https://api.openai.com/v1` 或 `https://api.deepseek.com/v1`。
4. 点击页面里的测试功能，确认模型能正常返回内容。
5. 测试通过后，把该配置作为后续开书和章节生成使用的模型。

推荐先用短提示词测试：

```text
请用一句话回复：模型连接正常。
```

如果出现 `An error occurred while sending the request` 或 `ResponseEnded`，优先检查 Endpoint、API Key、代理和模型输出上限。

## 3. 创建项目和分卷

在页面左侧或顶部工作上下文区域创建：

1. 项目：例如《潮汐塔》。
2. 分卷：例如第 1 卷《第三潮汐》。

后续所有世界观、角色、章节计划和正文都会绑定到当前项目或当前分卷。开始生成前，先确认页面顶部的项目和分卷已经选中。

## 4. 用 AI 开书生成基础素材

进入：

```text
AI 开书
/generate/novel-seed
```

AI 开书适合通过一段描述创建新小说，不建议一次直接生成很多章正文。推荐先生成开书需要的素材：

- 世界观
- 角色
- 势力
- 地点
- 卷设计
- 章节计划
- 章节蓝图

示例描述：

```text
我要写一本赛博玄幻小说。故事发生在被潮汐能量改造后的近未来城市，主角沈栀要潜入第三潮汐塔，调查潮汐财团隐藏的永生实验。整体风格偏悬疑、压迫、强情节推进，前 3 卷每卷 30 章。
```

建议参数：

```text
章节数：先填 10 - 30
卷数：先填 1 - 3
最大 Tokens：5000 - 7000
温度：0.75 - 0.85
```

长篇项目不要一次要求生成 3000 章计划。更稳的方式是先生成世界和大纲，再按卷或每 20 - 50 章分批扩展。

## 5. 检查章节计划和章节蓝图

AI 开书完成后，重点检查两个页面：

```text
章节计划
/generate/chapter_plans

章节蓝图
/generate/chapter_blueprints
```

检查重点：

- 章节是否从第 1 章开始按顺序排列。
- 标题是否连续重复。
- 简介是否过于相似。
- 角色、势力、地点是否符合当前卷。
- 核心事件是否能推动剧情，而不是只有背景介绍。

如果发现计划跑偏，可以在章节计划或章节蓝图页面跳回 AI 开书重新生成。重新生成计划通常比直接拿错误计划生成正文更省时间。

如果只是章节简介过于相似，可以在章节计划页使用“批量重写当前章节计划简介”，让系统按当前筛选范围重写简介。

## 6. 自动生成章节

进入：

```text
章节生成
/generate/chapters
```

推荐流程：

1. 选择项目和分卷。
2. 选择章节范围。
3. 先生成标题和简介预览。
4. 确认预览没有跑偏后，再启动自动生成。
5. 自动生成会作为后台任务运行，前台页面关闭后仍可继续执行。
6. 回到章节生成页查看任务状态和生成结果。

推荐 4000 中文字章节设置：

```text
预计字数：4000
最大 Tokens：7000 - 9000
最大重写次数：0 - 1
温度：0.75 - 0.85
```

Prompt 建议包含：

```text
请直接输出约 4000 个中文字符的完整章节正文，叙事完整，不要摘要，不要分点。
请使用自然小说段落排版：每段 3-6 句，段落之间只使用一个换行，不要一句一段。
```

如果生成门禁提示没有覆盖某个角色、势力、地点或关键词，先回到章节计划和蓝图检查字段是否写得过窄、带了多余符号，或正文确实没有写到对应内容。

## 7. 编辑章节

进入：

```text
章节编辑
/editor/chapters
```

这里可以查看和修改已经生成的章节正文。建议每批自动生成完成后，先抽查前 3 - 5 章：

- 标题是否与章节内容匹配。
- 开头是否承接上一章。
- 角色称呼是否一致。
- 地点和势力是否没有混用。
- 段落是否正常，不是一句一段。

修改后保存，系统会更新章节内容和字数。

## 8. 校验和修订

进入：

```text
校验工作台
/validate
```

校验用于发现规划和正文之间的问题，例如角色、地点、势力、情节连续性不一致。推荐每生成 5 - 10 章运行一次校验。

处理方式：

1. 校验提示规划字段错误：优先修章节计划或章节蓝图。
2. 校验提示正文缺内容：回到章节编辑补写，或带着错误信息重新生成该章。
3. 校验提示规则冲突：回到设计模块修世界规则、角色规则、势力规则或地点规则。

## 9. 天命协议流程

如果你希望更严格地按天命协议运行，进入：

```text
天命协议
/generate/tianming-protocol
```

推荐顺序：

```text
初始化 -> 绑定五件套 -> 大纲 -> 规划 -> 目录 -> 草案 -> 正文 -> 体检 -> 存档
```

五件套指：

```text
世界基石.md
世界观规则.md
角色档案.md
档案事件.md
文风样本.md
```

新手可以先用 AI 开书完成基础素材，熟悉流程后再使用天命协议页做更严格的知识库绑定和流程校验。

## 10. 常见问题

### 页面空白

先检查后端和前端是否都启动。开发模式需要同时运行：

```text
后端：http://localhost:38721
前端：http://localhost:38720
```

如果是 Docker 部署，只访问：

```text
http://localhost:38721
```

### AI 回复到一半超时

通常是单次输出太长、代理不稳定或上游模型限制导致。处理方式：

- 降低最大 Tokens。
- 减少一次生成的章节数量。
- 先生成素材和计划，不要一次生成大量正文。
- 检查代理和模型服务是否稳定。

### 章节标题连续重复

先不要直接批量生成正文。回到 AI 开书或章节计划页面，重新生成标题和简介预览，确认每章核心事件不同后再启动自动生成。

### 章节简介很像

在章节计划页使用“批量重写当前章节计划简介”。如果重写后仍然相似，说明大纲或卷设计给出的冲突变化不足，需要先强化每章核心事件。

### 生成门禁未通过

门禁会检查正文是否覆盖章节计划里的角色、势力、地点和关键词。常见原因：

- 计划字段写了正文不需要出现的实体。
- 实体名带了引号、括号或多余符号。
- 正文确实没有写到关键情节。
- 单章塞入的必写项太多，模型遗漏。

建议先清理章节计划字段，再重新生成该章。

### 想写几千章怎么办

系统可以按后台任务分批生成，但不建议一次创建几千章正文。推荐：

1. 先做全书战略大纲。
2. 按卷生成卷设计。
3. 每次只生成 20 - 50 章计划。
4. 先预览标题和简介。
5. 再按批次后台生成正文。
6. 每批完成后校验和修订，再进入下一批。

这样更容易发现跑偏，也更容易控制成本和上下文长度。

## 11. 数据备份

Docker 部署默认备份：

```text
docker/data/Storage
```

本地开发请以启动日志和配置文件中的 Storage 路径为准。备份前建议先停止服务，避免 SQLite 正在写入。

重要数据包括：

- SQLite 数据库
- 章节正文文件
- 上传文件
- 生成状态和任务记录

升级或重置数据库前，先备份运行数据目录。
