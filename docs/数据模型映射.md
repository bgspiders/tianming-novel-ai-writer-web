# 数据模型映射：JSON → SQLite

> **目的**：精确列出原 WPF 项目所有 JSON 持久化文件 → 新 SQLite 表的映射，作为阶段 1 实施依据。

## 一、原 JSON 存储概览

原项目所有数据靠文件系统存储（详见 [Framework/Common/Helpers/Storage/StoragePathHelper.cs](../../Framework/Common/Helpers/Storage/StoragePathHelper.cs)），分两类：

### 1.1 全局共享（非项目隔离）


## 二、SQLite Schema 总览（约 55 张表）

### 2.1 核心实体（5 张）

| 表 | 字段要点 | 索引 |
|----|---------|------|
| `projects` | id (PK), name, created_at, last_modified, version | `name UNIQUE` |
| `volumes` | id (PK), project_id (FK), volume_number, title, theme, milestone_text TEXT | `(project_id, volume_number) UNIQUE` |
| `chapters` | id (PK), volume_id (FK), chapter_number, title, word_count, summary TEXT, content_file_path, created_at, modified_at | `(volume_id, chapter_number) UNIQUE` |
| `source_books` | id (PK), name, author, genre... | 拆书来源 |
| `categories` | id (PK), module_type, name, parent_id, sort_order, is_built_in, is_enabled | `module_type + parent_id` 索引 |

### 2.2 设计层（7 张聚合根表，对应原 Modules/Design）

| 表 | 原 JSON 路径 | 字段类型亮点 |
|----|------------|-------------|
| `world_rules` | `Storage/Modules/Design/GlobalSettings/WorldRules/world_rules.json` | 10+ 个 string 字段 |
| `character_rules` | `Storage/Modules/Design/Elements/CharacterRules/character_rules.json` | 17 个 string（5 Tab） |
| `faction_rules` | `Storage/Modules/Design/Elements/FactionRules/faction_rules.json` | 9 个 string |
| `location_rules` | `Storage/Modules/Design/Elements/LocationRules/location_rules.json` | 含 `faction_id` FK + `landmarks/resources/dangers` 用 JSON 列 |
| `plot_rules` | `Storage/Modules/Design/Elements/PlotRules/plot_rules.json` | 16 个 string（4 Tab） |
| `creative_materials` | `Storage/Modules/Design/Templates/CreativeMaterials/creative_materials.json` | 18 个 string + `source_book_id` |
| `book_analyses` | `Storage/Modules/Design/SmartParsing/BookAnalysis/book_analysis.json` | + `chapter_count` `total_word_count` `crawled_at` |

所有设计表共有列：`id, name, category_id, is_enabled, source_book_id, created_at, updated_at`（继承自 `BusinessDataBase`）

### 2.3 生成层（4 张聚合根表）

| 表 | 原 JSON 路径 | 字段类型亮点 |
|----|------------|-------------|
| `outlines` | `Storage/Modules/Generate/GlobalSettings/Outline/outline_data.json` | 10 个 string + `dependency_versions JSON` |
| `volume_designs` | `Storage/Modules/Generate/Elements/VolumeDesign/volume_design_data.json` | + `volume_number`, `start_chapter`, `end_chapter`, 3 个 `referenced_*_names JSON` |
| `chapter_plans` | `Storage/Modules/Generate/Elements/Chapter/chapter_data.json` | + `chapter_number`, 3 个 `referenced_*_names JSON` |
| `chapter_blueprints` | `Storage/Modules/Generate/Elements/Blueprint/blueprint_data.json` | + `chapter_id FK`, `scene_number`, 多个 `opening/development/turning/ending/info_drop TEXT` |

### 2.4 追踪层（30+ 张表，从原 12 维事实快照 / 9 类变更声明拆出）

**角色状态轨迹**：
- `character_state_entries(character_id, project_id, name, base_profile)`
- `character_state_points(id, character_id, chapter_id, phase, level, abilities JSON, mental_state, key_event, importance)`
- `character_relationship_states(character_id, target_character_id, chapter_id, relation, trust)`

**势力 / 地点 / 物品 / 冲突状态轨迹**（同构）：
- `faction_state_entries / faction_state_points`
- `location_state_entries / location_state_points`
- `item_state_entries / item_state_points`
- `conflict_progress_entries / conflict_progress_points`

**时间线**：
- `chapter_timelines(chapter_id, time_period, elapsed_time, key_time_event)`
- `character_locations(character_id, current_location, last_updated_chapter)`
- `character_movements(id, character_id, chapter_id, from_location, to_location)`

**伏笔 / 情节点**：
- `foreshadowings(id, project_id, name, tier, is_setup, is_resolved, is_overdue, expected_setup_chapter, expected_payoff_chapter, actual_setup_chapter, actual_payoff_chapter)`
- `plot_points(id, project_id, chapter_id, context, keywords JSON, involved_characters JSON, importance, storyline)`

**归档**：
- `volume_fact_archives(volume_number, project_id, last_chapter_id, archived_at, snapshot_payload JSON)` 一行一卷

### 2.5 校验层（3 张）

- `validation_reports(id, chapter_id, validated_time, result, summary)`
- `validation_items(id, report_id, validation_type, name, result, details, suggestion)`

### 2.6 AI 配置层（3 张）

### 2.7 运行记录层（4 张）

- `generation_statistics(project_id, total_generations, first_pass_count, ...)`

### 2.8 索引与缓存层（4 张）

## 三、不入库的存储

### 3.1 章节正文（`.md` 文件继续保留）

原路径：`Storage/Projects/{projectName}/Generated/chapters/{chapterId}.md`
新路径：`Storage/projects/{projectId}/chapters/{chapterId}.md`

理由：
- 单章 3000-10000 字（~5-50 KB），数量随章节增长可达数千
- SQLite 大 TEXT 列影响读写性能
- 用户备份方便（直接打包 Storage 目录）
- `chapters` 表只存 `content_file_path` + `summary`

### 3.2 卷里程碑文本（`.txt` 文件继续保留）

原路径：`Storage/Projects/.../guides/milestones/vol{N}.txt`（上限 12000 字符）

迁移策略：可选——
- 保留文件，`volumes.milestone_text_file_path` 存路径
- 或入库，`volumes.milestone_text TEXT` 列（< 24 KB/卷，影响有限）

阶段 1 实施时确认。

### 3.3 上传图片 / 主题图片

原 WPF 用 [Microsoft.Win32.OpenFileDialog](../../Framework/Appearance/IntelligentGeneration/ImageColorPicker/) 选本地图片。

新方案：
- 前端 `<input type="file">` → POST `/api/uploads/image`
- 后端存到 `Storage/uploads/{yyyy}/{mm}/{uuid}.{ext}`
- `uploads` 表记录元数据

## 四、PublishService 的处理

[Services/Modules/ProjectData/Implementations/Packaging/PublishService.cs](../../Services/Modules/ProjectData/Implementations/Packaging/PublishService.cs) 原本会把多个 JSON 合并成 `Config/Design/elements.json` 等"打包发布"产物，供 AI 任务读取。

**Web 化后这套打包逻辑可完全删除**：
- AI 任务直接从 SQLite 查询所需数据
- 不再需要文件级合并 / 版本归档
- [Services/Modules/ProjectData/Implementations/Packaging/PackageHistoryService.cs](../../Services/Modules/ProjectData/Implementations/Packaging/PackageHistoryService.cs) 改为 `package_versions` 表 + 软删除

## 五、JSON 列 vs 子表的取舍

| 数据 | 推荐 |
|------|------|
| `ContextIdCollection`（15 个 ID 字段） | **JSON 列** — 整体作为 AI 上下文快照，无独立查询需求 |
| `GlobalSummary` | **JSON 列** — 缓存对象 |
| `LayerCompletionStatus` | **5 行子表** — 需要按 layer 查询 |
| `BlueprintData.SceneGuideEntries` | **子表** — 需要按场景查询 |
| `CharacterState.Relationships` | **子表** — 多对多查询 |
| `PlotPointEntry.Keywords/InvolvedCharacters` | **JSON 列** — 倒排索引由 `keyword_chapter_index` 单独承担 |
| `ValidationReport.Items` | **子表** — 数量可能很多，需要按 type 过滤 |

## 六、数据导入工具

阶段 1 必须实现：

```bash
dotnet TM.Web.Api.dll --import /path/to/old/Storage
```

工具步骤：
1. 扫描 `Storage/Modules/**/*.json` → 写入对应 SQLite 表
2. 扫描 `Storage/Projects/*/manifest.json` → 创建 `projects` 表项
3. 解析 `Config/guides/*.json` → 拆解到追踪层各子表
4. 复制 `Generated/chapters/*.md` 到新路径
5. 输出导入报告 `import-report.json`

幂等：多次导入时按 `id` 主键 upsert。
