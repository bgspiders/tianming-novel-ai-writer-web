## 二、LegacyBridge 接入策略

在 [web/backend/src/TM.Web.LegacyBridge/TM.Web.LegacyBridge.csproj](../backend/src/TM.Web.LegacyBridge/TM.Web.LegacyBridge.csproj) 中通过 `<Compile Include>` 源码包含，**不复制源码、不分叉**：

```xml
<ItemGroup>
  <!-- 包含 Services 全部 cs -->
  <Compile Include="..\..\..\..\..\Services\**\*.cs"
           Link="Legacy\Services\%(RecursiveDir)%(Filename)%(Extension)" />

  <!-- 包含 Modules 下的 Service 部分（排除 View/ViewModel） -->
  <Compile Include="..\..\..\..\..\Modules\**\Services\*.cs"
           Link="Legacy\Modules\%(RecursiveDir)%(Filename)%(Extension)" />

  <!-- 排除明确不可移植的文件 -->
  <Compile Remove="..\..\..\..\..\Services\Framework\SystemIntegration\TrayIconService.cs" />
  <Compile Remove="..\..\..\..\..\Services\Framework\AI\SemanticKernel\UIMessageItem.cs" />
</ItemGroup>
```

## 三、必须改造的关键点

### 1. 5 处 `GlobalToast.*` 调用 → 替换为 ILogger / 接口

| 文件 | 行号（约） | 原调用 | 改造方向 |
|------|-----------|--------|----------|
| `Services/Framework/AI/SemanticKernel/SKChatService.cs` | 多处 | `GlobalToast.Warning(...)` `GlobalToast.Error(...)` `GlobalToast.Info(...)` | 用 partial class 在 LegacyBridge 里给 `GlobalToast` 提供一个 Web 版替身类（接受调用但只写日志），避免改动原文件 |

具体做法：在 LegacyBridge 中新建 `Compatibility/GlobalToast.cs`：

```csharp
namespace TM.Framework.UI;
internal static class GlobalToast
{
    public static void Info(string msg) => Console.WriteLine($"[Info] {msg}");
    public static void Warning(string msg) => Console.WriteLine($"[Warn] {msg}");
    public static void Error(string msg) => Console.WriteLine($"[Error] {msg}");
}
```

让 `using TM.Framework.UI;` 解析到这个替身类。

### 2. `GenerationProgressHub` 静态 event → 注入式 IGenerationNotifier

原文件：[Services/Framework/AI/SemanticKernel/GenerationProgressHub.cs](../../Services/Framework/AI/SemanticKernel/GenerationProgressHub.cs)

```csharp
public static class GenerationProgressHub
{
    public static event Action<string>? ProgressReported;
    public static void Report(string message) => ProgressReported?.Invoke(message);
}
```

**问题**：静态 event 是全局广播，Web 单进程多连接时**会串号**（用户 A 看到用户 B 的章节生成进度，虽然单用户场景概率小但仍是隐患）。

**改造方案**：阶段 1 接入时新增 `GenerationProgressHubAdapter` 适配类：

```csharp
public static class GenerationProgressHub
{
    private static IGenerationNotifier? _notifier;
    private static AsyncLocal<string?> _currentRunId = new();

    public static void Bind(IGenerationNotifier notifier) => _notifier = notifier;
    public static void SetRunId(string runId) => _currentRunId.Value = runId;

    public static void Report(string message)
    {
        var rid = _currentRunId.Value;
        if (rid is not null && _notifier is not null)
        {
            _ = _notifier.StatusAsync(rid, message);
        }
    }
}
```

发布方调用 `GenerationProgressHub.Report(...)` 时通过 `AsyncLocal` 拿到当前请求的 runId，转发给 `IGenerationNotifier`（本阶段已实现 SignalR 版本）。

**调用现场**（9 处发布）：[Services/Framework/AI/SemanticKernel/Plugins/AutoRewriteEngine.cs](../../Services/Framework/AI/SemanticKernel/Plugins/AutoRewriteEngine.cs)、[Services/Framework/AI/SemanticKernel/Plugins/WriterPlugin.cs](../../Services/Framework/AI/SemanticKernel/Plugins/WriterPlugin.cs)

### 3. `StoragePathHelper` 改可注入

原文件：[Framework/Common/Helpers/Storage/StoragePathHelper.cs](../../Framework/Common/Helpers/Storage/StoragePathHelper.cs)

原行为：硬编码相对路径 `Storage/Services/...`，相对当前工作目录。

**改造**：增加 `SetBasePath(string)` 静态方法，由 ASP.NET Core 启动时读 `Storage:RootPath` 配置项调用一次。或者新建 `IStoragePathProvider` 抽象并把所有调用点替换（工作量大）。

最务实方案：保留静态 API，加 `SetBasePath` 方法，启动时 `StoragePathHelper.SetBasePath(builder.Configuration["Storage:RootPath"])`。

### 4. AI Key 加密持久化

原存储：[Storage/Services/AI/Library/](../../Storage/Services/AI/Library/) 下 JSON 文件**明文**存 API Key。

**改造**：
- SQLite `ai_api_keys` 表，`key_encrypted BLOB` 列
- 启动时生成 / 读取 `Storage/master.key`（32 字节，文件权限 0600）
