## 三、关键技术决策

1. **Schema 驱动的前端**:把每个模块的字段、Tab、列表列、字段类型(text/textarea/select/number/switch/tags/date)声明在 `moduleSchemas.ts` 这一个 TS 数据文件中。`DesignView.vue` 只有约 350 行,用同一套表格 + 同一个 `DesignFormField` 组件渲染 7 个模块。新增第 8 个模块只需:加 1 个 Schema + 1 个 API 模块 + 1 个 `apiMap` 入口,不动 UI 代码。
2. **CategoryService 用 ModuleType switch + 反射式 IQueryable 扩展**:`CountItemsByCategoryAsync` 用 `switch` 按 ModuleType 路由到对应 DbSet,共享 `GroupCountAsync<T>` 泛型方法。PromptTemplates 由于用字符串 Category(name)而非 CategoryId,单独实现 `CountPromptsByCategoryNameAsync` 按名匹配。
3. **删除分类的引用检查不按源书隔离**:`CountAllItemsAsync` 跨所有 SourceBook 统计 CategoryId == id 的实体,避免"按当前源书数为 0 通过删除,但其他源书还有引用"的逻辑漏洞(实际测试时发现的 bug,已修复)。
4. **InvalidOperationException → 400**:阶段 1.5+2 的中间件只把 `ArgumentException` 映射 400,本次新增的服务层用 `InvalidOperationException` 抛业务校验失败,扩展映射后才能正确返回 400 给前端,前端 axios 拦截器会把 `detail` 字段作为 `err.message` 弹出。
5. **`DesignBase` 接口让 TS 联合类型可统一**:7 个模块的 DTO 都实现 `DesignBase`(id/name/category/categoryId/isEnabled/sourceBookId/createdAt/updatedAt),前端 `DesignView.vue` 用 `Record<string, unknown>` 处理动态字段时只需把 list/get 返回值 `as unknown as Record<string,unknown>[]` 即可绕过 TS 严格类型。
6. **`/design` 重定向 + `/design/:module` 动态路由**:7 个模块共享一个 Vue 组件,通过路由参数切换。比 7 个独立路由文件更适合 schema 驱动模式。
7. **不在第一版做 FactionId picker**:LocationRule 的 FactionId 字段先以文本框接收(带 hint 提示)。让用户先复制粘贴 ID,picker 留到下次会话(后端的 reference 查询接口已就位)。
